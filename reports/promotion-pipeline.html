The pipeline

One durable state machine

A revision becomes active only after its package, build, and declared checks have succeeded.

01

Receive

Hash and retain the package before work is queued.

02

Validate

Parse the manifest and reject unsafe or inconsistent input.

03

Build

Compile or prepare inside the selected execution boundary.

04

Check

Run ordered, time-bounded commands with captured logs.

05

Activate

Commit the immutable revision and reconcile triggers.

Activation is the commit point.

A failed or cancelled deployment never replaces the currently active revision. Rollback performs a new transactional activation and restores the target revision’s triggers.

Operational safety

Failures become actions

Declared checks

Each manifest can define an ordered list of commands and explicit timeouts. The same contract works across languages.

Step diagnostics

Validate, build, check, and activate durations and bounded logs are recorded independently for fast diagnosis.

Cooperative cancellation

Queued work cancels immediately. Active work receives a persistent request that the worker observes without lying about completion.

Idempotent recovery

Retries link back to their source deployment and deduplicate repeated requests; rollback preserves immutable history.

Next: make retention explicit.

Source packages and build material are intentionally retained to make retry possible. The next best increment is a policy-driven garbage collector with protected active revisions, configurable age and count limits, a dry-run plan, and auditable deletions.
