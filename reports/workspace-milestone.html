Outcome

What changed

The operator sees the same system truth an external agent sees: immutable revisions, real triggers, lifecycle state, attempts, logs, output, and audit attribution.

Organized inventory

Automations are grouped by project and folder, searchable by operational metadata, and filterable by active or paused state. Latest-run health is visible without turning the product into a metric-card dashboard.

Safe intervention

Pause and resume are explicit lifecycle mutations. Manual runs carry a visible idempotency key, use the active immutable revision, and work even while an automation is paused for diagnosis.

Failure diagnosis

A run opens beside its automation with exact revision, event, timestamps, attempt count, error, logs, and structured output. A missing runtime secret is shown as the concrete configuration failure it is.

One control path

The workspace is a static client embedded in the Go binary. It calls the public management API and attributes mutations as workspace:operator; API-only deployments remain first-class.

Architecture

The important boundary

The interface is deliberately thin. Werkt’s API remains the product.

External coding agents use HTTP directly. Operators can use the embedded workspace.

No private admin API.

The browser receives no management token from the server. A supplied token stays in tab-scoped storage, and every mutation is visible in the same audit trail an agent reads.

Next: let agents deliver the artifact.

The remaining lifecycle gap is deployment. Today, an external agent can inspect, pause, resume, invoke, and diagnose—but deployment still assumes CLI access to a local package directory. The next milestone should add authenticated, idempotent artifact intake through the management API while preserving validation, immutable revisions, and the Husker boundary.

  1. 1 · IntakeStream a bounded package archive with digest and idempotency key.
  2. 2 · ValidateReturn structured manifest and build diagnostics before activation.
  3. 3 · BuildRun language-specific build steps inside the configured isolation backend.
  4. 4 · ActivateCreate and atomically select an immutable revision with audit attribution.
