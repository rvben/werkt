Security milestone · External ingress

Triggers are authenticated. Secrets stay references.

Werkt now accepts webhook and email events through per-trigger credentials, binds webhook signatures to time and replay identity, and injects runtime secrets into Python, Rust, Go, or any executable automation without persisting their values.

Verified end to end

Live HTTP, real PostgreSQL, process execution, and Husker request construction all passed.

01 / INGRESS

Trust is checked before work is queued.

The trigger manifest stores only the environment variable name. At request time, Werkt loads the active trigger policy, resolves the credential in memory, verifies the request, then delegates to the existing durable and idempotent event path.

01Receive bytes

Keep the exact request body intact for signing.

02Load active policy

Disabled automations and triggers fail closed.

03Resolve reference

Credential value comes from the control-plane environment.

04Verify request

Constant-time HMAC or bearer comparison before parsing.

05Queue once

The signed replay key returns the original run on retry.

HMAC-SHA256(secret, timestamp + "." + idempotency-key + "." + exact-body)
02 / BOUNDARY

References cross storage. Values do not.

This gives AI-authored automations a small, language-neutral contract while keeping control-plane credentials separate from deployment manifests and build environments.

03 / CONTROLS

Small controls, composed deliberately.

No one check carries the whole boundary. Authentication, freshness, idempotency, manifest validation, environment isolation, and fail-closed resolution work together.

✓
Replay-bound webhook HMAC

Timestamp, idempotency key, and exact body are signed together.

✓
Five-minute freshness window

Stale and future-dated signatures are rejected with 401.

✓
Per-trigger email bearer

The message is parsed only after its token passes verification.

✓
Required replay identity

Webhook keys and email Message-Ids prevent duplicate runs.

✓
Minimal process environment

Runtime children no longer inherit the full host environment.

✓
Fail before isolation starts

Missing runtime secrets fail before a process or VM is created.

✓
Strict manifest keys

Unknown trigger configuration and invalid variable names are rejected.

✓
Contract documented

README, OpenAPI, examples, and the security boundary agree.

What the run proved

The Go automation received its mapped secret and reported only a boolean presence signal. The management token was absent from the child. The Python automation consumed the authenticated email successfully.

  • Replay: created: false and the original run ID.
  • Isolation: no management or runtime secret appeared in API output.
  • Persistence: direct database scans found no credential values.
