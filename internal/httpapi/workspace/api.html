Werkt workspace/Management API

Operate Werkt without guessing.

OpenAPI 3.1 · v1. The same management contract powers agents, the CLI, and the workspace. Start with a least-privilege token, preserve idempotency keys, follow pagination links, and fetch individual runs only when you need logs or output.

Choose authority

Use read, operate, deploy, secrets, or retention tokens. A missing scope returns a typed insufficient_scope problem.

02

List summaries

Run lists omit logs and output. Continue with X-Werkt-Next-Cursor or the relative Link header.

03

Inspect exact state

Fetch a run or deployment by ID for authoritative diagnostics. Poll nonterminal work using Retry-After.

04

Verify the outcome

Audit by automation, action, actor, or time window. Every problem includes a stable code and request ID.

Find failed runs, then fetch logs

Keep the list lightweight; open only the run you are diagnosing.

curl -H "Authorization: Bearer $WERKT_MANAGEMENT_READ_TOKEN" \
  'https://werkt.example/api/v1/runs?status=failed&limit=25'

curl -H "Authorization: Bearer $WERKT_MANAGEMENT_READ_TOKEN" \
  'https://werkt.example/api/v1/runs/run_...'

Unsafe retries require a stable Idempotency-Key. Mutations should include X-Werkt-Actor unless the browser session supplies verified attribution.
